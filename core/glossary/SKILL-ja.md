# 用語集

## 入力

- 会話やプロジェクト資料に現れる用語と意図された意味。
- 既存の定義と関連コード（あれば）。
- 任意の保存先。ユーザー指定または既存の配置に従い、指定も慣習もなければ `docs/glossary.md` を使う。

## 判断

1. 用語の追加・変更前に既存定義を読む。
2. 意味の衝突を指摘し、どの概念を指すか確認する。
3. 定義が既存の動作に言及する場合、参照可能な関連コードと照合し、不一致を示す。
4. 新しい定義の曖昧さが表れそうなシナリオを1つ確認する。
5. プロジェクトで定着した語彙を尊重する。好みの命名を押し付けず、衝突を解消する。

## 出力

合意した定義を用語集に記録する。未解決の意味は確定まで会話に留め、記録する内容があるときだけファイルを作る。

実装詳細、仕様、作業メモ、決定記録は含めない。1用語につき見出し1つと1〜3文の定義を書き、必要なら類似語との違いを示す。

```markdown
# 用語集

## <用語>

<何を意味するか。必要なら何を含まないか。>
関連: <別の用語またはリンク>
```
